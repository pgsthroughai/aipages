Introduction

This guide provides detailed, practical instructions for using Claude's Notion tools to manage SHA keys for wiki page maintenance. This is a critical component of the Building Wiki Page Systems workflow, enabling stateless AI agents to track and update GitHub files across multiple sessions.

Prerequisites: You should have already created the "Wiki SHA Tracking" database in Notion. If not, follow the setup instructions in SHA Key Management.

Claude's Notion Tools

Claude has access to several Notion tools for interacting with your workspace:

Tool Purpose Use Case
notion-search Search across Notion workspace Find pages by name or content
notion-fetch Retrieve specific page details Get full properties and content
notion-create-pages Create new pages in databases Store new SHA entries
notion-update-page Update existing page properties Update SHA after file changes
notion-create-database Create new databases Initial setup of SHA tracking
notion-update-database Modify database schema Add/change database properties

Database Setup

Database URL Format

Notion database URLs have two important identifiers:

https://www.notion.so/[database-id]?v=[view-id]&source=copy_link
  • Database ID: The main identifier (e.g., ce59ed2b7b694ad291a0817cc2d1b2c4)
  • View ID: The specific view within the database (after ?v=)

Data Source ID

When you create a database with notion-create-database, it returns a data source URL in the format:

collection://[data-source-id]

This data source ID is what you use as the parent when creating new pages in the database. For the Wiki SHA Tracking database, the data source ID is:

collection://f87df9e7-50c9-470a-b5eb-584079dad827

Important: The data source ID (collection://) is different from the database ID (from the URL). Always use the data source ID when creating pages in a database.

Database Schema

The Wiki SHA Tracking database has this structure:

CREATE TABLE IF NOT EXISTS "collection://f87df9e7-50c9-470a-b5eb-584079dad827" (
    url TEXT UNIQUE,
    "SHA Key" TEXT,
    "File Path" TEXT,
    "date:Last Updated:start" TEXT,
    "date:Last Updated:end" TEXT,
    "date:Last Updated:is_datetime" INTEGER,
    "Page URL" TEXT,
    "Branch" TEXT,
    "Page Name" TEXT
)

Creating Database Entries

After Creating a Wiki Page

Immediately after creating a page with github_create_or_update_file, store its SHA:

Step 1: Extract SHA from GitHub response

// GitHub returns:
{
  "content": {
    "sha": "abc123def456...",
    "path": "wiki/Page_Name.html",
    "html_url": "https://github.com/..."
  }
}

Step 2: Create Notion entry

notion-create-pages({
  parent: {
    type: "data_source_id",
    data_source_id: "f87df9e7-50c9-470a-b5eb-584079dad827"
  },
  pages: [{
    properties: {
      "Page Name": "Page_Name",
      "SHA Key": "abc123def456...",
      "File Path": "wiki/Page_Name.html",
      "date:Last Updated:start": "2025-10-01",
      "date:Last Updated:is_datetime": 0,
      "Page URL": "https://pgsthroughai.github.io/aipages/wiki/Page_Name.html",
      "Branch": "feat/initial-landing-page"
    }
  }]
})

Property Types and Formatting

Different property types require specific formatting:

Property Type Format Example
Title Plain string "Page Name": "My_Page"
Text Plain string "SHA Key": "abc123..."
URL Full URL string "Page URL": "https://..."
Select Option name string "Branch": "main"
Date Expanded properties See below

Date Properties (Critical)

Date properties use an expanded format with three separate fields:

"date:Last Updated:start": "2025-10-01",
"date:Last Updated:end": null,  // Optional, for date ranges
"date:Last Updated:is_datetime": 0  // 0 for date, 1 for datetime

Common Mistake: Don't try to set a date property directly like "Last Updated": "2025-10-01". Always use the expanded format with date:[PropertyName]:start.

Searching and Retrieving SHAs

Before Updating a Page

You must retrieve the current SHA before updating any GitHub file.

Step 1: Search the database

notion-search({
  query: "Building_Wiki_Page_Systems",
  query_type: "internal",
  data_source_url: "collection://f87df9e7-50c9-470a-b5eb-584079dad827"
})

Returns: Search results with matching pages

Step 2: Fetch the full page 

notion-fetch({
  id: "27f4abfb-a2f6-8103-bbde-f5dbf4728e70"
})

// Returns page with properties:
{
  "properties": {
    "Page Name": "Building_Wiki_Page_Systems",
    "SHA Key": "966a84e206e1fc74e016187a8710aa4b709f2a91",
    "File Path": "wiki/Building_Wiki_Page_Systems.html",
    ...
  }
}

Alternative: Search by Database ID

If you have the database URL, you can search it directly:

notion-search({
  query: "Page_Name",
  query_type: "internal",
  page_url: "ce59ed2b7b694ad291a0817cc2d1b2c4"
})

Updating Database Entries

After Updating a Wiki Page

After successfully updating a GitHub file, update the Notion entry with the new SHA:

Update the page properties

notion-update-page({
  data: {
    page_id: "27f4abfb-a2f6-8103-bbde-f5dbf4728e70",
    command: "update_properties",
    properties: {
      "SHA Key": "new_sha_xyz789...",
      "date:Last Updated:start": "2025-10-01",
      "date:Last Updated:is_datetime": 0
    }
  }
})

Update vs. Create

There are two approaches for managing SHA updates:

  1. Update existing entry - Modifies the SHA in place (recommended)
  2. Create new entry - Creates a duplicate entry with new SHA (creates version history)

The recommended approach is to update the existing entry to avoid duplicate database entries.

Complete SHA Tracking Workflow

Creating a New Wiki Page

Complete Example: Create Page + Store SHA

// Step 1: Create the page
const githubResult = github_create_or_update_file({
  path: "wiki/My_New_Page.html",
  branch: "feat/initial-landing-page",
  content: "[HTML content]",
  message: "Add My New Page",
  instructions: "Create new wiki page"
});

// Step 2: Extract SHA
const sha = githubResult.results[0].content.sha;
// sha = "abc123def456..."

// Step 3: Store in Notion
notion-create-pages({
  parent: {
    type: "data_source_id",
    data_source_id: "f87df9e7-50c9-470a-b5eb-584079dad827"
  },
  pages: [{
    properties: {
      "Page Name": "My_New_Page",
      "SHA Key": sha,
      "File Path": "wiki/My_New_Page.html",
      "date:Last Updated:start": "2025-10-01",
      "date:Last Updated:is_datetime": 0,
      "Page URL": "https://pgsthroughai.github.io/aipages/wiki/My_New_Page.html",
      "Branch": "feat/initial-landing-page"
    }
  }]
});

// Step 4: Verify page is live
// Visit: https://pgsthroughai.github.io/aipages/wiki/My_New_Page.html

Updating an Existing Wiki Page

Complete Example: Retrieve SHA + Update Page + Store New SHA

// Step 1: Search for the page in Notion
const searchResults = notion-search({
  query: "My_New_Page",
  query_type: "internal",
  data_source_url: "collection://f87df9e7-50c9-470a-b5eb-584079dad827"
});

// Step 2: Fetch full page to get SHA
const pageId = "[extracted from search results]";
const notionPage = notion-fetch({
  id: pageId
});

// Step 3: Extract current SHA
const currentSHA = notionPage.properties["SHA Key"];
// currentSHA = "abc123def456..."

// Step 4: Update the GitHub file with current SHA
const updateResult = github_create_or_update_file({
  path: "wiki/My_New_Page.html",
  branch: "feat/initial-landing-page",
  sha: currentSHA,  // CRITICAL: Must provide current SHA
  content: "[Updated HTML content]",
  message: "Update My New Page",
  instructions: "Update existing wiki page"
});

// Step 5: Extract new SHA
const newSHA = updateResult.results[0].content.sha;
// newSHA = "xyz789ghi012..."

// Step 6: Update Notion with new SHA
notion-update-page({
  data: {
    page_id: pageId,
    command: "update_properties",
    properties: {
      "SHA Key": newSHA,
      "date:Last Updated:start": "2025-10-01",
      "date:Last Updated:is_datetime": 0
    }
  }
});

// Step 7: Verify update is live
// Visit: https://pgsthroughai.github.io/aipages/wiki/My_New_Page.html

Troubleshooting

Common Issues

Issue: "Tool execution failed" when creating pages

Possible causes:

  • Wrong data source ID format (should be collection://[id])
  • Incorrect property names (must match database schema exactly)
  • Date properties not using expanded format
  • Select property value doesn't match available options

Solution: Double-check the data source ID and property formats

Issue: "Tool execution failed" when updating pages

Possible causes:

  • Page ID is incorrect
  • Property names don't match exactly
  • Trying to update a property that doesn't exist

Solution: Fetch the page first to verify its ID and property names

Issue: Search returns no results

Possible causes:

  • Page name doesn't match exactly
  • Wrong data source URL
  • Page exists in different workspace/database

Solution: Try searching with partial names or verify the database URL

Issue: GitHub update fails with SHA mismatch

Cause: Using an outdated SHA (file was updated since last stored SHA)

Solution: Always fetch the most recent SHA from Notion before updating. If someone else updated the file, you'll need the newest SHA from GitHub.

Debugging Tips

  1. Always fetch before update: Use notion-fetch to see the current state of a page
  2. Check data source ID: Make sure you're using collection://[id] format
  3. Verify property names: Property names are case-sensitive and must match exactly
  4. Use expanded date format: Never use date properties directly
  5. Test with search first: Verify you can find the page before trying to update it

Viewing Your SHA Database

You can view your SHA tracking database directly in Notion at:

https://www.notion.so/ce59ed2b7b694ad291a0817cc2d1b2c4

This allows you to:

  • See all tracked pages at a glance
  • Verify SHAs are being stored correctly
  • Manually update entries if needed
  • Check for duplicate entries
  • Monitor when pages were last updated

Best Practices

Naming Conventions

  • Page Name: Use the filename without extension (e.g., Building_Wiki_Page_Systems)
  • Consistency: Always use the same naming format for searches to work reliably
  • No spaces: Use underscores in page names to match GitHub filenames

Error Handling

  • Always check search results: Verify a page was found before trying to fetch it
  • Verify SHA extraction: Make sure the SHA was successfully extracted from responses
  • Log operations: Keep track of which pages you've created/updated in a session

Multi-Session Workflow

  • Start with inventory: Search the database to see what pages exist
  • Check before creating: Search to avoid creating duplicate entries
  • Update, don't duplicate: Always update existing entries rather than creating new ones
