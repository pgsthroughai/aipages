Introduction

This guide covers the system-level approach to creating comprehensive, interconnected wiki page networks. While the Creating Wikipedia-Style Pages guide provides detailed instructions for building individual pages, this guide focuses on creating entire ecosystems of related content that work together as a cohesive knowledge base.

When building wiki systems with AI agents, you'll create multiple pages that reference each other, update existing pages with new information, and maintain consistency across the entire network. This requires careful planning, robust tracking mechanisms, and systematic workflows.

Related Resource: For detailed instructions on creating individual pages (research protocols, hyperlinking requirements, HTML structure), see the Creating Wikipedia-Style Pages guide.

SHA Key Management (CRITICAL)

⚠️ CRITICAL REQUIREMENT: When using the Zapier GitHub tools to update existing pages, you MUST provide the SHA key of the file. Without the correct SHA, updates will fail. Proper SHA management is essential for any wiki system.

What is a SHA Key?

A SHA (Secure Hash Algorithm) key is a unique identifier for each version of a file in GitHub. When you create a file, GitHub generates a SHA for it. To update that file later, you must provide its current SHA to prove you're working with the most recent version.

The Notion SHA Storage System

Since AI agents operate in stateless sessions, they cannot inherently remember SHA keys between conversations. The solution is to use Notion as a persistent storage system for SHA keys via a dedicated tracking database.

Database Structure

The "Wiki SHA Tracking" database contains the following properties:

  • Page Name (Title) - The name of the page file (e.g., "Building_Wiki_Page_Systems")
  • SHA Key (Text) - The current SHA hash for the file
  • File Path (Text) - Full path in repository (e.g., "wiki/Building_Wiki_Page_Systems.html")
  • Last Updated (Date) - When the SHA was last updated
  • Page URL (URL) - Live URL of the page
  • Branch (Select) - Git branch (feat/initial-landing-page or main)

Storage Protocol

Immediately after creating or updating any wiki page, the agent must:

  1. Extract the SHA from the GitHub response
  2. Create or update a page in the Notion database using the notion-create-pages or notion-update-page tool with:
    • Page Name as the title
    • SHA Key in the text field
    • Current date in Last Updated
    • Full file path and live URL
    • Branch name

Retrieval Protocol

Before updating an existing page, the agent must:

  1. Search the Notion database using notion-search with the page name as the query
  2. Fetch the matching page to get all properties
  3. Extract the SHA from the "SHA Key" property
  4. Use that SHA in the github_create_or_update_file call

Example Search Query

notion-search({
  query: "Building_Wiki_Page_Systems",
  query_type: "internal",
  data_source_url: "collection://[database-id]"
})

Important: Always retrieve and use the most recent SHA before any update operation. Using an outdated SHA will cause the update to fail.

Complete SHA Management Workflow

After Creating a New Page:

1. github_create_or_update_file(...)
   → Returns response with sha: "abc123..."

2. notion-create-pages({
     parent: {data_source_id: "[database-id]"},
     pages: [{
       properties: {
         "Page Name": "Page_Name",
         "SHA Key": "abc123...",
         "File Path": "wiki/Page_Name.html",
         "date:Last Updated:start": "2025-10-01",
         "date:Last Updated:is_datetime": 0,
         "Page URL": "https://pgsthroughai.github.io/...",
         "Branch": "feat/initial-landing-page"
       }
     }]
   })

Before Updating an Existing Page:

1. notion-search({
     query: "Page_Name",
     query_type: "internal",
     data_source_url: "collection://[database-id]"
   })
   → Returns search results

2. notion-fetch({id: "[page-id]"})
   → Extract SHA from properties

3. github_create_or_update_file({
     path: "wiki/Page_Name.html",
     sha: "abc123...",  ← REQUIRED FOR UPDATES
     content: "updated content...",
     ...
   })
   → Returns new SHA

4. notion-update-page({
     page_id: "[page-id]",
     data: {
       command: "update_properties",
       properties: {
         "SHA Key": "new_sha_xyz789...",
         "date:Last Updated:start": "2025-10-01",
         "date:Last Updated:is_datetime": 0
       }
     }
   })

System Architecture

Page Hierarchies

A well-organized wiki system typically has:

  • Hub Pages: Central topics that link to many related pages (e.g., "Artificial Intelligence", "Machine Learning Methods")
  • Detail Pages: Specific topics that provide deep information (e.g., "Transformer Architecture", "BERT Model")
  • Index Pages: Organizational pages that list related topics (e.g., "All AI Models", "By Year")
  • Landing Page: Main entry point that introduces the wiki and links to major sections

Link Network Planning

Before creating multiple pages, plan your linking structure:

  1. Identify Core Topics: What are the 5-10 main subjects?
  2. Map Relationships: How do topics connect to each other?
  3. Plan Bidirectional Links: If Page A links to Page B, should Page B link back?
  4. Create Navigation Paths: Ensure users can navigate between related topics

Multi-Page Creation Workflow

Phase 1: Planning

  1. Define Scope: List all pages you plan to create
  2. Establish Hierarchy: Determine which pages are central vs. supporting
  3. Plan Interlinking: Map which pages should link to which
  4. Set Naming Conventions: Consistent file naming (e.g., Technology_Name.html)

Phase 2: Core Page Creation

  1. Start with Hub Pages: Create the most important central pages first
  2. Follow Individual Page Protocol: Use the detailed creation guide
  3. Store SHA Keys: Add SHA to Notion database after each page creation
  4. Link Placeholders: Add links to pages you plan to create (they'll work once created)

Phase 3: Detail Page Creation

  1. Create Supporting Pages: Build pages that core pages link to
  2. Link Back to Core: Ensure bidirectional linking
  3. Store All SHAs: Add every new page to Notion database
  4. Verify Links: Test that internal links work correctly

Phase 4: Enhancement & Integration

  1. Update Hub Pages: Add newly created pages to hub page lists
  2. Retrieve SHAs Before Updating: Search Notion for SHA before each update
  3. Cross-Link Related Content: Add connections between detail pages
  4. Update Navigation: Ensure landing page and indexes reflect all new pages

Creating Interconnected Networks

Internal Linking Strategy

Strong wiki systems have rich internal linking:

  • Contextual Links: Link terms naturally within paragraphs
  • See Also Sections: Add "See Also" sections at the end of pages
  • Navigation Boxes: Create infoboxes that link to related topics
  • Category Pages: Build pages that organize topics by category

Link Maintenance

As your wiki grows:

  1. Regular Audits: Periodically check for broken internal links
  2. Backlink Tracking: When creating new pages, update existing pages that should link to them
  3. Link Density: Aim for 10-20 internal links per page minimum

System Maintenance

Updating Existing Pages

When you need to update a page:

# Step 1: Retrieve the current SHA from Notion
notion-search(query="Page_Name", data_source_url="collection://[db-id]")
notion-fetch(id="[page-id]") → extract SHA from properties

# Step 2: Make your changes
[modify content in memory]

# Step 3: Update with SHA
github_create_or_update_file(
    path="wiki/Page_Name.html",
    sha="current_sha_here",  ← CRITICAL
    content="updated content"
)

# Step 4: Update Notion with new SHA
notion-update-page(
    page_id="[page-id]",
    properties={"SHA Key": "new_sha", "date:Last Updated:start": "2025-10-01"}
)

Version Tracking

The Notion database creates a natural audit trail:

  • Each page entry shows when it was last updated
  • You can view the entire database to see all tracked pages
  • The "Last Updated" date helps track page freshness

Batch Updates

When updating multiple pages:

  1. Retrieve All Needed SHAs First: Search Notion for each page's SHA before starting
  2. Track Updates: Keep a list of which pages you've updated
  3. Update All Notion Entries: Update each page's SHA in Notion after GitHub update
  4. Verify Changes: Check that all updates were successful

Best Practices

SHA Management Best Practices

  • ✅ Always store SHA immediately after creating/updating a page
  • ✅ Use exact page name for the Notion entry title
  • ✅ Include all metadata (file path, URL, branch, date)
  • ✅ Search before every update to get the current SHA
  • ❌ Never guess or reuse old SHAs
  • ❌ Never skip SHA storage, even for "small" changes

System Organization

  • Consistent Naming: Use the same capitalization and underscore conventions
  • Clear File Structure: Organize pages logically in directories if needed
  • Comprehensive Landing Page: Maintain a central index of all pages
  • Regular Audits: Periodically review and improve existing pages

Content Quality

  • Follow Individual Page Guidelines: Apply all standards from the detailed guide
  • Maintain Consistency: Use similar structure and styling across all pages
  • Update Related Pages: When adding information, update all relevant connected pages
  • Verify All Links: Test both internal and external links regularly

Multi-Session Continuity

When working across multiple sessions:

  • Check Notion Database: View the SHA tracking database to see all existing pages
  • Reliable SHA Retrieval: Search Notion by page name to get current SHA
  • Browse Existing Pages: Use browserless_fetch_a_site_s_html to see what's already created
  • Start Each Session with Inventory: Review the Notion database before adding more pages

Quick Reference: Complete Creation Cycle

For Each New Page:
1. Research topic (web_search, web_fetch)
2. Create HTML content following template
3. github_create_or_update_file(...) → get SHA
4. notion-create-pages(parent={data_source_id}, properties={...SHA...})
5. Verify page is live at URL

For Each Page Update:
1. notion-search(query="Page_Name")
2. notion-fetch(id) → extract SHA
3. Modify content
4. github_create_or_update_file(sha=old_SHA, ...) → get new SHA
5. notion-update-page(properties={"SHA Key": new_SHA, ...})
6. Verify update is live

For System Management:
1. View Notion SHA tracking database to see all pages
2. Plan new pages and updates
3. Create/update following protocols above
4. Maintain Notion SHA database
5. Verify all internal links work
6. Update hub pages with new content

Conclusion

Building wiki page systems requires attention to both individual page quality and system-level organization. The SHA management system via Notion is essential for maintaining and updating your wiki over time. By following these protocols and combining them with the detailed page creation guide, you can build comprehensive, interconnected knowledge bases that grow and evolve effectively.

Remember: Every page creation or update must include SHA storage in Notion. This is not optional—it's the foundation of long-term wiki maintenance.
