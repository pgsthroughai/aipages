Understanding GitHub SHA Keys

What is a SHA in GitHub?

A SHA identifies:

  • File SHA: Unique ID for specific file content version
  • Commit SHA: Unique ID for a commit

For API updates: Use FILE SHA, not commit SHA

Critical: SHA Must Match Current File

When updating files via GitHub API, the SHA MUST match the current file version.

Error if mismatch: "file.html does not match [old-sha]"

Cause: File was updated after SHA was saved in Notion

Notion Search Workflow

Step 1: Search for Database

notion-search
query: "Wiki SHA Tracker"
query_type: "internal"

Step 2: Fetch Database Structure

notion-fetch
id: [database-id-from-search]

Returns: schema, properties, data source URL (collection://...)

Step 3: What Does NOT Work

notion-search
data_source_url: "collection://..."
query: ""

Result: Tool execution failure

Step 3: What DOES Work

notion-search
query: "SHA Key" (or other distinctive term)
query_type: "internal"

Searches all workspace, including database entries

Step 4: Fetch Individual Pages

notion-fetch
id: [page-id-from-search]

Returns all properties including SHA Key, File Path, Branch

GitHub Integration

One SHA Parameter - Two Uses

Creating NEW file: OMIT sha parameter

Updating existing file: MUST include current file sha

Creating New File (No SHA)

github_create_or_update_file
branch: "feat/initial-landing-page"
path: "wiki/New_File.html"
content: [html]
message: "Create new file"
(NO sha parameter)

Updating Existing File (SHA Required)

github_create_or_update_file
branch: "feat/initial-landing-page"
path: "wiki/Existing_File.html"
content: [html]
sha: "dd44a65b3c1951df7cbcdcff044334881cfe69e1"
message: "Update file"

SHA must be current or update fails

Key Observations

  1. Single SHA parameter in GitHub tool - used only for updates
  2. No separate commit SHA needed - commit created automatically
  3. New file creation returns a new file SHA in response
  4. File SHA changes every time content changes
  5. Notion sync is manual - update SHA in Notion after GitHub changes

Best Practices

  • Create new files when SHA uncertain
  • Update Notion immediately after GitHub changes
  • Use workspace search, not data_source_url
  • Search with distinctive terms from database
  • Fetch pages individually by ID

Common Mistakes

  • Trying to search with data_source_url parameter
  • Using outdated SHA from Notion
  • Confusing commit SHA with file SHA
  • Forgetting to update Notion after GitHub changes
