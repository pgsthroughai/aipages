Introduction

This guide documents a working solution for integrating Tana, a powerful knowledge management tool, with Claude through Zapier's Model Context Protocol (MCP). The integration leverages 0CodeKit's Python code execution capabilities to enable Claude to create and manage nodes in a Tana workspace programmatically.

The Model Context Protocol (MCP) is an open standard developed by Anthropic that standardizes how AI applications interact with external tools and data sources. Zapier provides an MCP server that connects AI assistants to over 8,000 applications, enabling them to take real-world actions through natural language commands.

Prerequisites

Before implementing this integration, you will need:

  • Tana Account: An active Tana account with a workspace
  • Tana API Token: Generated from your Tana workspace settings
  • Claude Access: Access to Claude (claude.ai or Claude Desktop)
  • Zapier MCP: Configured Zapier MCP server connected to your Claude instance
  • 0CodeKit Integration: The 0CodeKit app added to your Zapier MCP tools

Setup Process

Step 1: Generate Tana API Token

In your Tana workspace:

  1. Click your profile in the lower left corner
  2. Navigate to Settings > API Tokens
  3. Select the workspace you want to integrate
  4. Click Create token
  5. Save the generated JWT token securely
Security Note: Your Tana API token provides full access to your workspace. Store it securely and never share it publicly. Consider using secure storage methods like encrypted password managers or email to yourself (not in plain text files or shared documents).

Step 2: Configure Zapier MCP

Visit your Zapier MCP configuration page and:

  1. Create or select an existing MCP server
  2. Click + Add tool
  3. Search for "0CodeKit"
  4. Select the action "Run Python Code"
  5. Connect your 0CodeKit account if not already connected
  6. Save the configuration

Step 3: Connect Claude to Zapier MCP

Follow the Zapier MCP setup instructions for your Claude client:

  • Claude.ai: Add the MCP server URL in your organization settings
  • Claude Desktop: Configure the MCP server in your Claude Desktop application

Technical Details

Architecture Overview

The integration works through a chain of protocols and services:

  1. Claude → Communicates via MCP protocol
  2. Zapier MCP Server → Translates MCP calls to Zapier actions
  3. 0CodeKit → Provides Python code execution environment
  4. Python Script → Makes HTTP POST requests using the requests library
  5. Tana Input API → Receives and processes the data

Tana Input API Endpoint

The Tana Input API endpoint is:

https://europe-west1-tagr-prod.cloudfunctions.net/addToNodeV2

This RESTful API endpoint accepts JSON payloads with an Authorization header containing your Bearer token.

API Rate Limits

The Tana Input API has the following limitations:

  • Rate Limit: 1 call per second per token
  • Batch Limit: Maximum 100 nodes per call
  • Size Limit: Maximum 5,000 characters per request
  • Workspace Limit: Maximum 750,000 nodes per workspace

Capabilities and Limitations

What You Can Do

  • ✅ Create new nodes in INBOX, SCHEMA, or any specific node ID
  • ✅ Add descriptions to nodes
  • ✅ Create child nodes with hierarchical structures
  • ✅ Apply supertags to nodes for categorization
  • ✅ Add fields with structured data
  • ✅ Format text using Markdown (bold, italic, strikethrough)
  • ✅ Create references, dates, URLs, and files

Current Limitations

  • ❌ Read Operations: The Tana Input API currently only supports writing data, not reading
  • ❌ Search: Cannot query or search existing Tana content via API
  • ❌ Updates: Limited update capabilities (only node names can be modified)
  • ❌ Deletion: Cannot delete nodes via API
Important: According to Tana's documentation, read capabilities are "on the roadmap" but not yet available. This integration is currently write-only.

Code Examples

Basic Node Creation

Here's a simple example of creating a node in your Tana INBOX:

import requests

# Configuration
TANA_API_URL = "https://europe-west1-tagr-prod.cloudfunctions.net/addToNodeV2"
TANA_TOKEN = "your-jwt-token-here"

# Payload
payload = {
    "targetNodeId": "INBOX",
    "nodes": [{
        "name": "My First Node",
        "description": "Created via Claude and Zapier MCP"
    }]
}

# Make request
response = requests.post(
    TANA_API_URL,
    json=payload,
    headers={
        'Authorization': f'Bearer {TANA_TOKEN}',
        'Content-Type': 'application/json'
    },
    timeout=30
)

# Return result
result = {
    'success': response.status_code == 200,
    'data': response.json() if response.status_code == 200 else response.text
}

result

Creating Nodes with Children

Create a node with nested child nodes:

payload = {
    "targetNodeId": "INBOX",
    "nodes": [{
        "name": "Project Planning",
        "children": [
            {"name": "Research phase"},
            {"name": "Development phase"},
            {"name": "Testing phase"}
        ]
    }]
}

Applying Supertags and Fields

To apply supertags and add fields, you need the supertag's node ID:

payload = {
    "targetNodeId": "INBOX",
    "nodes": [{
        "name": "Meeting with John",
        "supertags": [{"id": "YOUR_SUPERTAG_ID"}],
        "children": [
            {
                "type": "field",
                "attributeId": "YOUR_FIELD_ID",
                "children": [{
                    "dataType": "date",
                    "name": "2025-10-15"
                }]
            }
        ]
    }]
}

Troubleshooting

Common Issues

404 Error - Page Not Found:

  • Ensure you're using the correct endpoint: /addToNodeV2
  • The base URL should be: https://europe-west1-tagr-prod.cloudfunctions.net

401 Error - Unauthorized:

  • Verify your Tana API token is correct and not expired
  • Ensure the token is formatted as: Bearer YOUR_TOKEN
  • Check that there are no extra spaces in the token

Timeout Errors:

  • Increase the timeout parameter (default is 30 seconds)
  • Reduce the payload size if sending many nodes
  • Check your network connection

Rate Limit Errors:

  • Remember the 1 call per second limit
  • Add delays between sequential requests if needed

Debugging Tips

  1. Always test with a simple payload first
  2. Use try/except blocks to catch and log errors
  3. Check the response status code and message
  4. Verify your token by testing it manually with curl or Postman
