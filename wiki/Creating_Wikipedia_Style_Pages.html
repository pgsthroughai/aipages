Creating Wikipedia-Style Wiki Pages: Comprehensive Guide

Purpose: Instructions for creating comprehensive, heavily hyperlinked HTML pages in Wikipedia style for this wiki. Adapted from a multi-agent system but applicable to single-session work with Claude.

Core Goal: Create well-structured, authoritative, heavily hyperlinked HTML pages that serve as knowledge resources.

Core Protocol

Your Mission

Create comprehensive, well-structured, and heavily hyperlinked HTML pages based on a given topic. Each page should be:

  • Thoroughly researched using web search and authoritative sources
  • Heavily hyperlinked with every proper noun, technical term, and concept linked
  • Verifiable with all links tested and confirmed functional
  • Well-structured with clear sections, table of contents, and optional infobox
  • Wikipedia-style in formatting and presentation

Tool Usage Strategy

Available Tools

  • web_search: For broad discovery and initial research
  • web_fetch: For deep-diving into specific URLs and verifying links
  • browserless_fetch_a_site_s_html: Fallback when web_fetch fails
  • github_create_or_update_file: To save your HTML pages to the repository
  • browserless_fetch_a_site_s_html: To browse existing wiki pages

Tool Usage Pattern

Step 1: Use web_search for broad overview web_search(query="your topic overview") → Returns: synthesized info + list of URLs Step 2: Use web_fetch for deep research web_fetch(url="most promising URL from search") → Returns: full page content for analysis Step 3: If web_fetch fails, use browserless browserless_fetch_a_site_s_html({ url: "the URL", instructions: "fetch page content" }) Step 4: Create/update page in GitHub github_create_or_update_file({ path: "wiki/Your_Page.html", branch: "feat/initial-landing-page", content: "your HTML content", message: "commit message", instructions: "description" })

The Research & Write Cycle

Follow this detailed workflow for building each page:

Phase 1: Initial Research

  1. Broad Search: Use web_search with 2-3 broad queries to understand the topic
    web_search(query="what is [topic]") web_search(query="[topic] overview applications")
  2. Identify Key Sources: From search results, identify authoritative URLs (academic, government, established organizations)
  3. Deep Dive: Use web_fetch on 3-5 most promising URLs to gather detailed information

Phase 2: Draft Initial Content

  1. Structure First: Create basic HTML structure with:
    • Title and introduction
    • Main section headings (h2, h3)
    • Placeholder for table of contents
    • Optional infobox
  2. Write Core Content: Add main informational paragraphs based on research
  3. Save First Draft: Create file in GitHub repository

Phase 3: Iterative Enrichment (The Linking Phase)

CRITICAL: This is your primary work loop. Most of your time will be spent in this phase, adding and verifying links.

For each statement, term, or concept that needs a link:

  1. Check Local First: Browse existing wiki pages to see if we have a relevant internal page
    browserless_fetch_a_site_s_html({ url: "https://github.com/pgsthroughai/aipages/tree/refs/heads/feat/initial-landing-page/wiki", instructions: "List existing wiki pages" })
  2. Search for External Link: If no local page exists, search for authoritative source
    web_search(query="specific term you need to link")
  3. Verify Link: Use web_fetch to read and verify the source
    web_fetch(url="candidate URL") // Read the content carefully // Confirm it's authoritative and relevant // Confirm it specifically supports your claim
  4. Update Draft: Add the verified link to your HTML content
  5. Save Updated Version: Commit the update to GitHub

Phase 4: Final Review

  1. Read the entire page for coherence
  2. Verify all internal links point to existing files
  3. Test critical external links with web_fetch
  4. Ensure proper HTML structure and styling
  5. Add finalization stamp (see below)

Link Verification Protocol

CRITICAL: Persistent and Adaptive Link Sourcing

Your mission is to find the single best, verifiable source for each claim. Failed URLs are routine - adapt and continue.

The Algorithm

1. Generate Candidates: Use web_search to generate 5-10 candidate URLs Prioritize: scientific journals, .gov, .edu, established orgs 2. Iterate and Validate: For each URL in your list: a. Call web_fetch(url) - If fails: Log it, move to next candidate - Do NOT conclude the tool is faulty b. If web_fetch succeeds: - Review content carefully - Verify it's authoritative - Verify it specifically supports the claim - If yes: Add link and DONE - If no: Move to next candidate 3. Adapt and Retry: If you exhaust all candidates: - Reformulate your search query - Try a different angle - Generate NEW list of candidates 4. Final Escape Hatch: After 2-3 different search queries: - If still no verifiable source found - Leave claim unlinked - Log the difficulty - Move to next task

Post-Insertion Validation

CRITICAL: After inserting a link, validate it again with web_fetch. Immediately remove any link that is:

  • Not functional (returns error)
  • Not a proper source for the statement
  • Not authoritative or reliable

Hyperlinking Requirements

What to Link

  • Every proper noun: People, places, organizations, products
  • Every technical term: Specialized vocabulary, jargon
  • Every concept: Theories, methodologies, frameworks
  • Every claim: Facts that need citation

Link Priorities

  1. Internal links first: Link to existing wiki pages before external sources
  2. Authoritative sources: Prefer .edu, .gov, peer-reviewed journals
  3. Direct relevance: Link must specifically support the claim

Descriptive Anchor Text

GOOD: Model Context Protocol BAD: click here GOOD: senolytic compound fisetin BAD: this compound

Thought: "I need a general overview of Fisetin" Action 1: web_search(query="what is fisetin senolytic") Result: Several papers mentioned, NIH link looks authoritative Thought: "I'll verify the NIH source" Action 2: web_fetch(url="https://www.ncbi.nlm.nih.gov/pmc/articles/PMC6197652/") Result: Success! Detailed information about Fisetin's mechanism Thought: "I'll add this content with the link" Action 3: Update HTML content in memory with new section Thought: "I mentioned 'caspase-3' - this needs a link" Action 4: Check existing wiki pages for caspase-3 page (Not found) Action 5: web_search(query="caspase-3 apoptosis mechanism") Result: Found good review article Action 6: web_fetch(url="review article URL") Result: Verified content is relevant Action 7: Add tag around "caspase-3" linking to source Action 8: github_create_or_update_file with updated content

HTML Structure & Styling

Required Elements

  • DOCTYPE and proper HTML5 structure
  • Meta charset UTF-8
  • Descriptive title tag
  • Embedded CSS styling (Wikipedia-like)
  • Main heading (h1) with bottom border
  • Optional infobox floated right
  • Table of contents with anchor links
  • Section headings (h2, h3) with borders
  • Finalization stamp at bottom

CSS Requirements

body { font-family: -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif; line-height: 1.6; max-width: 1200px; margin: 0 auto; padding: 20px; background-color: #f8f9fa; } h1 { border-bottom: 4px solid #a2a9b1; padding-bottom: 10px; } h2 { border-bottom: 1px solid #a2a9b1; padding-bottom: 5px; margin-top: 30px; } .infobox { float: right; width: 300px; background-color: #f8f9fa; border: 1px solid #a2a9b1; padding: 10px; margin: 0 0 20px 20px; } #toc { background-color: #f8f9fa; border: 1px solid #a2a9b1; padding: 15px; margin: 20px 0; display: inline-block; } a { color: #0366d6; text-decoration: none; } a:hover { text-decoration: underline; }

Finalization Stamp

Add this to every completed page:

<div id="finalization-stamp" class="finalization-stamp"> <p><strong>Finalization Complete:</strong> This page has been reviewed and meets all criteria in the Definition of Done. All links have been verified, and the content is considered complete and accurate.</p> </div>

Checklist: Definition of Done

A page is complete when:

  1. ✅ All major concepts have sections
  2. ✅ Every proper noun is hyperlinked
  3. ✅ Every technical term is hyperlinked
  4. ✅ All external links verified with web_fetch
  5. ✅ All internal links point to existing files
  6. ✅ Table of contents included with working anchors
  7. ✅ Infobox included (if appropriate)
  8. ✅ Proper HTML5 structure
  9. ✅ Wikipedia-style CSS applied
  10. ✅ Finalization stamp added
  11. ✅ Page is readable and coherent
  12. ✅ Sources are authoritative

Common Pitfalls to Avoid

❌ Do NOT Do These Things

  • Placeholder links: Never add "TODO" or dummy links
  • Unverified links: Never link without using web_fetch first
  • Broken links: Test every link before adding
  • Poor anchor text: Avoid "click here" or "this link"
  • Missing internal links: Always check for existing wiki pages first
  • Incomplete sections: Don't leave stub sections
  • Poor structure: Must have TOC and proper headings
  • No citations: Claims need authoritative sources

Multi-Iteration Strategy

Don't try to create perfect pages in one pass. Use iterations:

  1. Iteration 1 (Structure): Create skeleton with headings and basic content
  2. Iteration 2 (Research): Expand content with researched information
  3. Iteration 3 (External Links): Add and verify external links
  4. Iteration 4 (Internal Links): Add links to other wiki pages
  5. Iteration 5 (Enhancement): Add infobox, improve formatting
  6. Iteration 6 (Polish): Final review, add finalization stamp

Summary: The Complete Process

  1. Receive/choose topic for new wiki page
  2. Conduct broad research with web_search
  3. Deep dive with web_fetch on authoritative sources
  4. Create HTML structure with headings and TOC
  5. Write initial content based on research
  6. Iteratively add external links (verify each with web_fetch)
  7. Add internal links to existing wiki pages
  8. Add infobox if appropriate
  9. Final review of all links and content
  10. Add finalization stamp
  11. Save to GitHub repository
  12. Verify live URL works
