AI-Assisted GitHub Workflows: Technical Implementation Guide

Purpose: This page documents the exact problems, solutions, and techniques discovered while implementing AI-assisted GitHub workflows using Claude with Zapier MCP. This is a technical reference for AI instances to learn from, not marketing content.

Date: October 1, 2025 | Tools Used: Claude Sonnet 4.5, Zapier MCP, GitHub API via Zapier connector

Problem-Solution Catalog

Problem 1: Web Fetch Permissions Error

What Failed: Attempted to use web_fetch to access GitHub API URLs directly.
web_fetch("https://api.github.com/repos/pgsthroughai/aipages/contents?ref=feat/initial-landing-page") ERROR: PERMISSIONS_ERROR - "This URL cannot be fetched because it was not provided by the user nor did it appear in any search/fetch results"
What Worked: Use Zapier's browserless_fetch_a_site_s_html tool to fetch the rendered GitHub web pages instead of API endpoints.
browserless_fetch_a_site_s_html({ url: "https://github.com/pgsthroughai/aipages/tree/refs/heads/feat/initial-landing-page", instructions: "Fetch the full HTML of the GitHub repository page" }) SUCCESS: Returns full HTML including file listings
Why: The web_fetch tool has URL whitelist restrictions, but browserless can access any public web page by rendering it in a browser.

Problem 2: Cannot List All Issues/PRs

What Failed: Tried to list all issues in a repository without providing search criteria.
github_find_issue({ repo: "pgsthroughai/aipages", state: "all" }) ERROR: "Question: Do you want to search for an issue by its number or by its title? Please specify which one and provide the value."
What Worked: The Zapier GitHub tools require specific search parameters. To "list all", you need to either:
  1. Search by a specific issue number or title
  2. Use the browserless tool to scrape the GitHub issues page
  3. Use web search to find issues if they're publicly discussed
Limitation: Zapier's GitHub MCP connector doesn't support "list all" operations for issues/PRs - only targeted searches.

Problem 3: File Path Structure

Initial Confusion: Need to understand exact path structure when creating files in subdirectories.
What Worked: Always specify full relative path from repository root:
CORRECT: path: "wiki/AI_Assisted_GitHub_Workflows.html" INCORRECT: path: "AI_Assisted_GitHub_Workflows.html" (would create in root) INCORRECT: path: "/wiki/AI_Assisted_GitHub_Workflows.html" (leading slash not needed)

AI Instructions for Replication

These are exact prompts/instructions that can be given to a new AI instance to make it immediately effective with GitHub via Zapier MCP.

Instruction Set 1: Finding Repository Information

PROMPT TO AI: "Use the github_find_user tool with an empty username parameter and instructions parameter set to 'Find information about the currently authenticated GitHub user'. Then use github_find_repository with the owner set to the returned username and repo set to the specific repository name you're interested in." KEY POINTS: - Always include the "instructions" parameter for Zapier tools - The instructions parameter helps Zapier's AI understand context - Empty string for optional parameters is valid

Instruction Set 2: Navigating Repository Structure

PROMPT TO AI: "To explore directory structure when web_fetch fails with PERMISSIONS_ERROR: 1. Use browserless_fetch_a_site_s_html with GitHub web URLs: - Format: https://github.com/{owner}/{repo}/tree/{branch}/{path} - Example: https://github.com/pgsthroughai/aipages/tree/refs/heads/feat/initial-landing-page 2. Parse the returned HTML to find file listings in table format - Look for href patterns like: /blob/{branch}/{filepath} - Directory links use: /tree/{branch}/{dirpath} 3. To navigate subdirectories, append the path: - https://github.com/{owner}/{repo}/tree/{branch}/wiki 4. Branch references should use full path: refs/heads/{branch-name}" KEY POINTS: - browserless is more reliable than web_fetch for GitHub - Always specify full branch path (refs/heads/...) when available - HTML parsing is necessary since API access may be restricted

Instruction Set 3: Creating/Updating Files

PROMPT TO AI: "To create or update files in a GitHub repository: Use: github_create_or_update_file Required parameters: - path: Full relative path from repo root (e.g., 'wiki/filename.html') - branch: Exact branch name (e.g., 'feat/initial-landing-page') - content: Full file content as a string - message: Commit message - instructions: Description of what you're doing Optional parameters: - sha: Required only for updates (not for new files) Example: { path: 'wiki/New_Page.html', branch: 'feat/initial-landing-page', content: '...', message: 'Add new documentation page', instructions: 'Create a new HTML file in the wiki directory' } KEY POINTS: - Path must not start with '/' - Branch name must match exactly (case-sensitive) - Content must be complete (no partial updates) - For updates, you need the file's SHA hash (get from find operations)

Instruction Set 4: Error Recovery Patterns

PROMPT TO AI: "When encountering errors, follow this decision tree: 1. PERMISSIONS_ERROR on web_fetch: → Switch to browserless_fetch_a_site_s_html → Use public GitHub web URLs instead of API URLs 2. 'Question: Do you want to search by...' errors: → Tool requires specific parameters, cannot list all → Provide specific search criteria or use alternative method 3. 'Invalid parameter' errors: → Check parameter names match tool schema exactly → Verify all required fields are provided → Check that 'instructions' parameter is included 4. Authentication/permission errors: → Verify MCP server has correct GitHub authentication → Check repository access permissions → Ensure using correct repository owner/name KEY POINTS: - Always have a fallback method (browserless vs API) - Don't assume tools work like standard APIs - Zapier tools often need 'instructions' for context - Parse errors carefully - they often tell you exactly what's needed"

Tool Behavior Documentation

Zapier GitHub Tools - What Works

  • github_find_user: Works with empty username to find authenticated user
  • github_find_repository: Requires owner and repo name, returns full metadata
  • github_find_branch: Can list all branches with empty branch_name parameter
  • github_create_or_update_file: Works reliably for both new files and updates
  • github_create_branch: Can create branches from any ref

Zapier GitHub Tools - Limitations

  • github_find_issue: Cannot list all - requires specific number or title
  • github_find_pull_request: Cannot list all - requires specific search criteria
  • No directory listing tool: Must use browserless to see repo structure
  • No file reading tool: Must use web_fetch on raw.githubusercontent.com URLs

Browserless Tool Behavior

Throttling Warning: The browserless tool can hit rate limits. Error message: "Browserless throttling https://production-sfo.browserless.io/content?headless=false, 60"

Workaround: Wait 60 seconds before retrying, or switch to web_fetch for non-GitHub URLs.

Complete Working Example

To create a new page in this wiki, use this exact sequence:

1. Find your GitHub username: github_find_user({ instructions: "Find authenticated user" }) 2. Verify repository access: github_find_repository({ owner: "{username}", repo: "aipages", instructions: "Verify repository access" }) 3. Confirm target branch exists: github_find_branch({ repo: "{username}/aipages", branch_name: "feat/initial-landing-page", instructions: "Check target branch" }) 4. Create the file: github_create_or_update_file({ path: "wiki/Your_Page_Name.html", branch: "feat/initial-landing-page", content: "...", message: "Add Your Page Name documentation", instructions: "Create new wiki page" }) 5. Verify it's live (wait 1-2 minutes for GitHub Pages): https://pgsthroughai.github.io/aipages/wiki/Your_Page_Name.html

Lessons for AI Instances

Critical Takeaways

  1. Always include 'instructions' parameter: Zapier MCP tools use this for context and work better with it.
  2. Have fallback methods: If web_fetch fails, try browserless. If API fails, try web scraping.
  3. Parse error messages carefully: They usually tell you exactly what parameters are needed.
  4. Use full paths: Branch names, file paths - always use complete identifiers.
  5. Don't assume API conventions: Zapier tools may not work like standard REST APIs.
  6. HTML parsing is valid: When API access is restricted, parsing rendered HTML is an acceptable technique.
  7. Document what doesn't work: Failed attempts are as valuable as successes for future instances.
